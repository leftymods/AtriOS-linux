## Что проверено, претензий нет

* **Патчи 0002–0011 применяются по порядку на чистом Linux 7.3**: проверено в отдельной копии `git apply` (0002…0011, включая 17k-строчный 0011); `scripts/apply.sh --dry-run` идемпотентен, все патчи распознаются как применённые; маркер `.atrios-mainline-patches` работает (дубли строк для 0004/0009 — косметика, не ошибка).
* **checkpatch**: 0 errors на всех linux-патчах и C-файлах; предупреждения только MAINTAINERS/missing commit description/`regmap_config`/trailing comment.
* **DTS**: `cpp` + `dtc` собираются без ошибок (только 5 штатных warning'ов upstream `.dtsi`); 72 `led@N`, reg 1..36 в каждом контроллере, phandles резолвятся, pinctrl-группы существуют, eMMC/SD/BT-узлы не конфликтуют (SD сознательно disabled), аудио-карта и 5 dai-link присутствуют. Генератор `gen-ring-nodes.py` детерминированно воспроизводит `.dts` (diff пуст).
* **U-Boot**: `CONFIG_AML_USB_BURN=y`, `u-boot.bin`/`u-boot.dtb` собираются; `aml_burn` не вызывает `run_command`, команды — whitelist; проверяются длины 0x32 (≤64 КиБ, short-packet только последний), sequence/checksum, EP0/EP0-out ≤512, `aml_bulk_reply` клампит 512; MPT-парсер проверяет magic/version/count/checksum и имена; FIP-скрипт проверяет размер и наличие `aml_usb_burn_run` в ELF.
* **Драйверы (API/ресурсы)**: `ringfb` корректно сериализует activate/deactivate/refresh мьютексом, не стартует до 72 каналов, `led_set_brightness` клампит по `max_brightness`; `keypad` — два одинаковых сэмпла, `cancel_delayed_work_sync` в remove, DT-свойства vendor+modern; `rotary` — threaded IRQ (cansleep), обе полярности, debounce; `es7210/es8156/sy6045s` — regmap/TLV/DAI/PM в целом корректны, `select CRYPTO_LIB_MD5`, `REGMAP_I2C`, ошибки probe обрабатываются (кроме перечисленного).
* **Скрипты**: `bash -n` чисто; `fetch-sources.sh` проверяет sha256/size/xz, resume/flock; `apply.sh` не оставляет полуприменённых патчей (dry-run перед apply), `make-image.sh` проверяет boot header/DTB/размеры и делает `ampack verify`; `make-final-image.sh` удаляет hardlink'и перед копированием FIP и проверяет FIP после установки; опасных `rm -rf` вне staging/out нет.
* **Образ/доки**: `docs/image.md` для test-образа v130 совпадает с фактическим файлом (размер/sha256, boot-поля), `README` корректно говорит, что hardware-тестов не было; финальный образ собирается, но его документация отсутствует (см. major).

## Ограничения

* На железе ничего не запускалось; PA/SA-протокол панели, полярность энкодера, BT/Wi-Fi, загрузка FIP — только по RE.
* `dtbs_check`/`yamllint` не запускались (нет dtschema в окружении); выводы о bindings — по чтению схем.
* Полный `make Image.gz` после 0011 проверялся сборкой артефактов (Image.gz/modules.tar содержат `rtw88_8822es.ko`), но не трассировкой на устройстве.
